# LinkFlow CRM

Статическая мини-CRM для задач линкбилдера. В ней можно создавать пользователей, назначать им задачи, вести URL и количество сделанных ссылок. Откройте `index.html` локально или разместите файл через GitHub Pages.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него все файлы из этой папки.
2. В разделе **Settings → Pages** выберите источник **Deploy from a branch**.
3. Укажите ветку `main` и папку `/(root)`, затем сохраните настройку.
4. GitHub покажет адрес опубликованной страницы в разделе Pages.

Все проекты, пользователи, задачи и счётчики сохраняются в браузере на текущем устройстве. Кнопка «Экспорт» создаёт резервную копию в JSON, а кнопка «Импорт» восстанавливает данные из неё.

## Хранение данных

GitHub Pages публикует статические файлы. Проекты, пользователи и задачи хранятся в PostgreSQL-базе проекта Supabase. У каждой учётной записи отдельная запись CRM, а правила доступа Supabase разрешают прочитать и изменить только собственную запись.

Локальная копия остаётся в браузере и помогает продолжить работу при временной недоступности сети. После подключения отображается статус синхронизации в шапке CRM.

## Регистрация и вход

Для регистрации и входа страница использует Supabase Auth. Создайте проект в Supabase, включите Email Auth и внесите в `supabase-config.js` адрес проекта и публичный publishable key. В настройках Supabase добавьте адрес GitHub Pages в список Redirect URLs. Затем откройте `supabase-schema.sql` в SQL Editor Supabase и выполните скрипт создания таблицы с правилами доступа.

Пароль передаётся напрямую в Supabase Auth. В `supabase-config.js` допускается только публичный publishable key. Secret key предназначен для сервера и в GitHub Pages его размещать нельзя.

## Индексация

Файл `robots.txt` запрещает индексацию, а метатег `noindex` добавлен в страницу. Роботы поисковых систем обычно соблюдают эти правила. Адрес сайта и исходные файлы остаются доступными тому, кто получил ссылку. Вход через Supabase защищает доступ к интерфейсу CRM.
